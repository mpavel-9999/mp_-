Связанные документы: [02_db_architecture.md](02_db_architecture.md) — таблицы и функции, [03_implementation_spec.md](03_implementation_spec.md) — ТЗ на реализацию, [04_product_architecture.md](04_product_architecture.md) — схемы взаимодействия.

## 1. Участники и понятия

| Понятие | Смысл в алгоритме |
| --- | --- |
| Клиент | Агент в роли CLIENT, создаёт запрос (сделку) |
| Поставщик | Агент в роли PROVIDER или SUBAGENT, откликается на запрос |
| Компания | Агент в роли COMPANY: назначает субагентам сервисы и период, видит их санкции (салон — компания, мастер Игорь — субагент) |
| Администратор | Агент в роли ADMIN; только ему можно включить режим тестирования |
| Сделка | Запрос клиента: услуга (вариант дерева), гео, период, радиус зоны, минимальный рейтинг поставщика, своя цена |
| Публикация (окно) поставщика | Разовое объявление доступности: точка или маршрут, окно времени, минимальная цена. Пример: «парковочное место свободно 18:00–18:30», «еду из А в Б» |
| Отклик | Предложение поставщика по сделке: цена и точка предложения |
| Код закрытия | Динамический QR или цифровой ключ, который поставщик показывает клиенту |
| Режим тестирования | Признак агента-администратора: положение задаётся курсором на карте, QR подтверждается без камеры. Во всём остальном агент обычный |

### Режимы сервиса (настройки `service_setting`, наследуются по дереву)

| Настройка | Значения | Влияние на алгоритм |
| --- | --- | --- |
| `geo_mode` | `point` / `route` / `none` | Одна точка, маршрут А → Б или без гео |
| `place_mode` | `provider` / `client` / `online` | Где оказывается услуга; определяет правило зоны (п. 2.1) |
| `price_unit` | `fixed` / `hour` / `km` | Единица цены |
| `max_parallel_deals` | число | Сколько согласованных сделок поставщик держит одновременно (п. 2.8) |
| `slot_required` | 0 / 1 | Нужна ли публикация окна, чтобы получать запросы (парковка, такси — 1) |
| `close_method` | `QR` / `KEY` | Способ подтверждения закрытия (п. 5) |

## 2. Статусы сделки и переходы

```
INIT ─► MATCHING ─► OFFERS ─► AGREED ─► CONTACT ─► CLOSED
            │           │        │          │
            │           │        │          └──────► NOT_CLOSED (нет закрытия через 24 ч)
            │           │        ├─────────────────► NOT_CLOSED
            ├───────────┴──► EXPIRED (нет согласования к началу периода)
            │
 любой до CLOSED ──► CANCEL_FREE | CANCEL_CLIENT | CANCEL_PROVIDER (правила п. 5.2–5.4)
```

| Из | В | Кто | Условие |
| --- | --- | --- | --- |
| INIT | MATCHING | Система | Запрос сохранён, поля запроса заполнены |
| MATCHING | OFFERS | Система | Пришёл первый отклик |
| OFFERS | AGREED | Клиент | Нажал «Согласовать» по активному отклику |
| AGREED | CONTACT | Система | Стороны ближе `near_radius_m` (гео-услуги) |
| CONTACT | CLOSED | Клиент | Принят действующий код закрытия |
| AGREED | CLOSED | Клиент | Только для `place_mode = online` (код `KEY`) |
| MATCHING, OFFERS | EXPIRED | Система | Наступило `period_start`, согласования нет |
| AGREED, CONTACT | NOT_CLOSED | Система | Через `not_closed_after_h` после вопроса «Услуга оказана?» |
| до CLOSED | CANCEL_* | Сторона | Правила отмены п. 5.2–5.4 |

Переходы хранятся в справочнике `DEAL_TRANSITION`; триггер на `deal` отклоняет любой другой переход и сам пишет запись в `deal_status_log` (П-1). Статусы CLOSED, EXPIRED, NOT_CLOSED, CANCEL_* — финальные.

## 3. Алгоритм

### 0) Общие правила

- 0.1) Каждое изменение статуса проверяется по таблице переходов и логируется триггером; приложение и API не пишут `deal_status_log` напрямую (П-1).
- 0.2) Все условия подбора реализованы в одной функции `provider_can_offer(deal, agent)`. Её используют: список входящих запросов поставщика, автоотклик и триггер на `deal_offer` (П-2).
- 0.3) Номера записей выдают последовательности (`identity`), не `max + 1` (П-3).
- 0.4) Периоды сравниваются как интервалы `tsrange`, поэтому периоды через полночь и на несколько дней работают одинаково (П-6).
- 0.5) Все тексты интерфейса и уведомлений берутся из `glossary_text` на языке агента, без перевода — RUS.
- 0.6) Агент в режиме тестирования участвует в сделках с обычными агентами. Рейтинг, отзывы, антифрод, санкции, уведомления и финансы работают для него так же, как для всех (В-10, Н-8).

### 1) Инициация — Клиент создаёт запрос (INIT → MATCHING)

- 1.1) Выбирает услугу: поиск по названию, пути и синонимам (`v_service_search`) или переход по дереву «категория → сервис → вариант». Сделка создаётся на варианте; настройки и поля наследуются от сервиса и категории.
  - 1.1.1) Для такси вариант — класс авто: Эконом, Комфорт, Комфорт+, Бизнес (Н-6).
  - 1.1.2) Клиент может начать с публикации поставщика на карте (п. 1.9): услуга, точка и окно подставляются из неё.
- 1.2) Указывает гео:
  - `point` — точка услуги (по умолчанию текущее положение);
  - `route` — точка подачи П и точка назначения Н;
  - `none` — без гео.
- 1.3) Указывает период: дата/время «с» и «по», например 24.10.2026 18:00–18:15.
- 1.4) Задаёт радиус зоны, например 100 м (для `none` не задаётся).
- 1.5) Задаёт минимальный рейтинг поставщика (`provider_rating_min`, необязательно).
- 1.6) Заполняет поля запроса (`service_attribute.attr_scope = request`): гос. номер, число пассажиров, адрес, описание задачи. Обязательные поля проверяются по `is_required`, формат — по `attribute_type`.
- 1.7) Видит прогноз цены `price_forecast_min..max` (П-5): пересечение диапазонов цен подходящих поставщиков в зоне и медиана закрытых сделок сервиса за окно `forecast_window_min` в ячейке `forecast_grid_m`. Если истории нет — только диапазоны поставщиков.
- 1.8) Может указать свою цену `client_price`; по умолчанию — медиана прогноза (Н-1).
- 1.9) Для такси видит оценку стоимости по классу: `max(порог, цена за км × расстояние П → Н по дорогам OSM)` по тарифам водителей рядом (Н-5, Н-7).
- 1.10) Нажимает «Найти». Система проверяет, что у клиента нет сделок без выставленных баллов (п. 5.6); иначе запрос не создаётся.

### 2) Подбор — Система находит поставщиков (MATCHING)

Поставщик получает запрос, только если выполнены все условия (функция `provider_can_offer`):

- 2.1) Гео по `place_mode` (В-1):
  - `provider` (парковка, салон): точка предложения поставщика (его публикация или `agent_service.geo`) внутри зоны клиента;
  - `client` (мастер, курьер): точка клиента внутри зоны обслуживания поставщика (`agent_service.zone_radius_m`);
  - `online` (репетитор): гео не проверяется.
- 2.1.1) Такси (`geo_mode = route`, В-8). Водитель публикует маршрут: текущая точка А с радиусом rA (например, 300 м) и точка назначения Б с радиусом rB (например, 1 000 м). Запрос подходит, если одновременно:
  - точка подачи П — в коридоре маршрута А → Б по дорогам ±rA;
  - точка назначения Н — в коридоре маршрута ±rA или в радиусе rB вокруг Б;
  - направление совпадает: П на маршруте раньше Н.
  
  Если водитель не указал Б — подходит любой запрос с П в радиусе rA вокруг А.
- 2.1.2) Класс авто: вариант сделки совпадает с подключённым вариантом водителя или входит в список принимаемых классов `accepts_variants` (Комфорт может брать Эконом) (Н-6).
- 2.2) Время (В-2):
  - если у сервиса `slot_required = 1` — период клиента внутри окна активной публикации поставщика;
  - иначе — период клиента внутри рабочего времени `agent_service.work_time_from..to` (если задано).
- 2.3) Цена: прогноз или цена клиента пересекается с ценами поставщика (`price_min..price_max`; для `km` — оценка поездки не ниже порога водителя).
- 2.4) Рейтинг поставщика по сервису не ниже `provider_rating_min`.
- 2.5) Рейтинг клиента по сервису не ниже `client_rating_min` поставщика. Нет рейтинга по сервису — берётся `rating_start` (4,0), в интерфейсе пометка «новичок» (В-4).
- 2.6) Доступ к сервису (В-12, Н-9):
  - поставщик — действующая подписка, в пакет которой входит сервис (категория в пакете открывает все её узлы);
  - субагент — сервис назначен ему компанией на период, не выходящий за подписку компании, и входит в её пакет.
- 2.7) Поставщик не заблокирован на период сделки (`agent_sanction.action = block`).
- 2.8) Не превышен лимит одновременных сделок (В-13, Н-10): число сделок поставщика в AGREED или CONTACT, пересекающихся по времени, меньше `max_parallel_deals`.
  - обычная парковка: 1 (одно место — одна сделка в момент времени);
  - частная парковка (отдельный сервис): ёмкость `agent_service.capacity`; номер места выдаётся при согласовании;
  - салон — компания, каждый мастер — субагент с лимитом 1.
- 2.9) Поставщик — не сам клиент.
- 2.10) Система рассылает запрос подходящим поставщикам (уведомление `NEW_REQUEST`) и запускает автоотклики (п. 3.1).

### 3) Выбор — Поставщик откликается (MATCHING → OFFERS)

- 3.1) Автоотклик (`agent_service.is_auto = 1`): уходит на **все** подходящие запросы (Н-3). Цена (В-5):
  - цена клиента, если она в диапазоне `price_min..price_max` поставщика;
  - иначе медиана прогноза, ограниченная диапазоном поставщика и округлённая до `auto_price_round` (50 тг).
- 3.2) Ручной режим: поставщик видит все подходящие запросы и сам выбирает, на какие откликнуться. Пример (В-2): место освобождается в 18:10; запрос А «18:15 за 800» и запрос Б «18:30 за 1 800» — поставщик может подождать и откликнуться только на Б.
- 3.3) Подтверждает время и цену (для себя: локация, спрос, рейтинг); для такси цена считается по его тарифу: `max(price_min, unit_price_min × расстояние П → Н)` (Н-7).
- 3.4) Заполняет поля отклика (`attr_scope = offer`): время подачи, марка и номер авто.
- 3.5) Нажимает «Откликнуться». Триггер повторно проверяет `provider_can_offer`; отклик получает статус `active`. Клиенту — уведомление `NEW_OFFER`.

### 4) Согласование — Клиент выбирает (OFFERS → AGREED → CONTACT)

- 4.1) Видит активные отклики списком и на карте в порядке `offer_sort_1..3`; при равенстве раньше тот, кто откликнулся первым. Отклики вне зоны клиента не выводятся.
- 4.2) Поставщик показан псевдонимом, рейтингом и ценой: «Петр_Парковка · ★ 4.43 · 1000 тг».
- 4.3) До согласования точка смещена на `approx_offset_m` (зависит от сервиса и рейтинга поставщика). Направление — `md5(deal_offer_id || секрет сервера)`; расстояние показывается от смещённой точки интервалом («до 50 м», «50–100 м») (П-4).
- 4.4) Нажимает «Согласовать». В одной транзакции:
  - отклик → `selected`, остальные отклики сделки → `declined`, их поставщикам — уведомление `OFFER_DECLINED` (добавлено в Э5 шаг 8: сделка пропадает из списков поставщика, иначе об отказе не узнать);
  - другие активные отклики этого поставщика на пересекающееся время сверх `max_parallel_deals` → `withdrawn`, их клиентам — уведомление;
  - сделке записываются поставщик, цена, номер места (частная парковка), секрет кода закрытия;
  - статус AGREED, поставщику — уведомление `AGREED`.
- 4.5) Клиенту открываются: имя поставщика, точная точка, ссылки на маршрут (Яндекс, 2ГИС, Google).
- 4.6) Сближение: если расстояние между положениями сторон не больше `near_radius_m` (парковка 300 м, такси 200 м) — статус CONTACT, уведомление `NEAR`, открываются поля `show_stage = near` (гос. номер, телефон). Контактными данными в смысле п. 5.2 считаются только они (В-9).

### 5) Закрытие сделки

- 5.1) Поставщик оказал услугу и нажимает «Закрыть сделку» — у него открывается код закрытия.
- 5.1.1) Клиент получил услугу и нажимает «Закрыть сделку» — ждёт код. Поставщику приходит уведомление `CLOSE_REQUEST`, экран кода открывается у него автоматически.
- 5.1.2) Код закрытия (В-7, Н-4) — настройки сервиса:
  - `close_method = QR`: QR живёт `close_qr_ttl_s` = 10 с;
  - `close_method = KEY`: ключ из `close_code_len` = 6 цифр живёт `close_key_ttl_s` = 60 с;
  - у каждого сервиса значения можно переопределить; для `online` всегда `KEY`;
  - код = HMAC-SHA256(секрет сделки, номер интервала) → 6 цифр; сервер принимает код текущего и предыдущего интервала.
- 5.1.3) Клиент сканирует QR или вводит ключ. Сервер проверяет код, статус и (для гео-услуг) что сделка в CONTACT. Статус CLOSED.
- 5.1.4) Режим тестирования:
  - если сделок несколько — агент выбирает сделку из списка;
  - «Сканировать QR» — без камеры: приложение берёт действующий код у сервера и отправляет его;
  - «Предоставить QR» — второй агент сделки получает код автоматически и подтверждает его без нажатий.
- 5.2) Отмена без штрафа — CANCEL_FREE (В-3, Н-11):
  - до согласования — всегда;
  - после согласования — в течение `cancel_free_min` (5 мин, такси 2 мин) и до CONTACT;
  - если опаздывает другая сторона и это подтверждено гео (положение не приближается к точке после начала периода).
  
  Отзыв по желанию.
- 5.3) Отмена поставщиком в остальных случаях — CANCEL_PROVIDER: падение рейтинга поставщика, причина обязательна (`CANCEL_REASON` или текст). Клиенту — уведомление об односторонней отмене и форма баллов.
- 5.4) Отмена клиентом в остальных случаях — CANCEL_CLIENT: падение рейтинга клиента, причина обязательна. Поставщику — уведомление и форма баллов.
- 5.5) Сроки (В-6, Н-12):
  - MATCHING или OFFERS без согласования к `period_start` → EXPIRED, без последствий;
  - AGREED или CONTACT через `closing_ask_after_min` (30 мин) после `period_end` → обеим сторонам вопрос «Услуга оказана?» с кнопкой «Закрыть сделку»;
  - без закрытия через `not_closed_after_h` (24 ч) → NOT_CLOSED; если стороны были рядом — сигнал антифроду `BYPASS_GEO`.
- 5.6) Баллы обязательны обеим сторонам после CLOSED и после односторонней отмены (для пострадавшей стороны). Пока оценка не поставлена, агент не может создать запрос или откликнуться (В-11). Комментарий необязателен.

### 6) Антифрод: блокировки и ограничения

- 6.1) Эпизод фрода — обход платформы и неуплата сборов:
  - встреча сторон по гео-меткам без закрытой сделки (`BYPASS_GEO`);
  - отмена после показа гос. номеров в радиусе 300 м (`NEAR_CANCEL`);
  - накрутка рефералов: фиктивные аккаунты с одного устройства, карты или номера (`FAKE_REFERRALS`).
  
  Первый эпизод — предупреждение о понижении рейтинга. Повтор — понижение системного рейтинга и предупреждение о блокировке.
- 6.2) Больше двух эпизодов при подозрительно положительных отзывах **и** падении выручки (недополученная выручка больше принесённой) — блокировка на неделю, повторно на месяц, повторно на год.
- 6.3) Компания получает уведомление `SANCTION` о санкциях своих субагентов (Н-9).
- 6.4) Реферальные начисления от фиктивных аккаунтов переводятся в `cancelled`.

## 4. Частные сценарии

### 4.1 Парковка: публикация места (В-2, Н-2, Н-3)

1. Поставщик публикует место: точка, окно 18:00–18:30, минимальная цена.
2. Клиенты видят свободные места на карте (точка со смещением). Нажатие открывает запрос с подставленными услугой, точкой и окном.
3. Клиент А: 18:15 за 800 тг; клиент Б: 18:30 за 1 800 тг.
4. Авто-режим: поставщик откликается на оба запроса; место достаётся тому, кто первым согласует. Второй отклик снимается (`withdrawn`), клиент получает уведомление.
5. Ручной режим: поставщик сам выбирает, на какой запрос откликнуться.

### 4.2 Такси по пути (В-8, Н-5…Н-7)

1. Водитель публикует маршрут А (rA = 300 м) → Б (rB = 1 000 м), класс Комфорт, тариф: порог 700 тг, 150 тг/км.
2. Запрос клиента Эконом: подача П в 200 м от маршрута, назначение Н в 600 м от Б, П раньше Н по ходу движения — запрос подходит (Комфорт принимает Эконом).
3. Цена отклика = max(700, 150 × длина П → Н по дорогам). Фиксируется при согласовании.

### 4.3 Частная парковка (В-13, Н-10)

Отдельный сервис с ёмкостью `capacity`. Отклик возможен, пока число пересекающихся по времени согласованных сделок меньше ёмкости. Номер места выдаётся при согласовании и пишется в поля отклика.

### 4.4 Онлайн-услуга (В-7)

Без гео и без статуса CONTACT. Закрытие из AGREED ключом `KEY` (6 цифр, 60 с), который поставщик называет клиенту.

## 5. Режим тестирования

## 8. Отложено на следующие этапы

- Алгоритм прогноза цены сверх П-5 (спрос/предложение по сетке и окну).

- Сканирование QR камерой в обычном режиме (CameraX / ML Kit) — в прототипе сканер Google Code Scanner, если доступны сервисы Google Play.
- Офлайн-пакет карты MBTiles с CDN.

## 9. Журнал решений

| № | Вопрос | Решение |
| --- | --- | --- |
| В-1 | Правило зоны | По `place_mode`: provider — точка предложения в зоне клиента; client — точка клиента в зоне поставщика; online — без гео |
| В-2 | Рабочее время | Окно публикации поставщика; авто-режим — по порядку подачи, ручной — выбор поставщика |
| В-3 | Отмена после согласования | Бесплатно `cancel_free_min` и до CONTACT, позже — штраф инициатору; опоздание другой стороны по гео — без штрафа |
| В-4 | Новый клиент без рейтинга | `rating_start` = 4,0 и пометка «новичок» |
| В-5 | Цена автоотклика | Цена клиента в диапазоне поставщика, иначе медиана прогноза в диапазоне, округление до 50 |
| В-6 | Зависшие сделки | EXPIRED к началу периода; вопрос «Услуга оказана?»; NOT_CLOSED |
| В-7 | Закрытие онлайн-услуг | Способ закрытия в настройках сервиса: QR + время жизни, KEY + длина + время жизни |
| В-8 | Такси | Маршрут водителя А → Б, коридор ±rA, радиус rB вокруг Б, направление; тариф водителя |
| В-9 | Контактные данные | Только поля `show_stage = near` |
| В-10 | Тестовые агенты | Только администраторы; участвуют с обычными агентами; всё работает по одной схеме |
| В-11 | Обязательные баллы | Без оценки нельзя создать запрос или откликнуться |
| В-12 | Субагент | Сервисы и период назначает компания; компания получает уведомления о санкциях |
| В-13 | Пересечение сделок | Одно место — одна сделка; частная парковка — отдельный сервис с ёмкостью |
| Н-1 | Цена клиента | Поле «Моя цена» в запросе |
| Н-2 | Окно поставщика | Таблица публикаций; свободные места видны на карте |
| Н-3 | Автоотклик | На все подходящие запросы, побеждает первое согласование |
| Н-4 | Время жизни кода | QR 10 с, KEY 60 с, настраивается по сервису |
| Н-5 | Маршрут | По дорогам OSM |
| Н-6 | Класс авто | Варианты дерева такси + `accepts_variants` |
| Н-7 | Тариф | `price_min` (порог) и `unit_price_min` (за км/час) в `agent_service` |
| Н-8 | Шестерёнка | Видят все |
| Н-9 | Ограничения субагента | Период ≤ подписки компании, сервисы из её пакета |
| Н-10 | Ёмкость | `max_parallel_deals`, номер места при согласовании; салон — компания, мастер — субагент |
| Н-11 | `cancel_free_min` | 5 мин, такси 2 мин |
| Н-12 | Сроки | 30 мин после периода — вопрос, 24 ч — NOT_CLOSED |
| П-1 | Переходы статусов | Справочник переходов + триггер с логированием |
| П-2 | Подбор | Функция `provider_can_offer` + триггер на `deal_offer` |
| П-3 | Номера записей | Последовательности |
| П-4 | Смещение точки | md5 с серверным секретом, расстояние интервалом |
| П-5 | Прогноз цены | Диапазоны поставщиков в зоне + медиана закрытых сделок |
| П-6 | Время | `tsrange`, периоды через полночь |
| 6.2 | Условие блокировки | Подозрительные отзывы **и** падение выручки |
