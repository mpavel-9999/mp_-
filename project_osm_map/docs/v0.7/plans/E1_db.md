## Проверка связности

- **Порядок загрузки.** Триггеры, которые работают и в режиме загрузки (`trg_agent_testing`, `trg_agent_service_assign`, `trg_agent_position`), требуют уже загруженных данных. Поэтому `is_testing` ставится обновлением после ролей (шаг 9), а назначение сервиса субагенту — обновлением после подписок (шаг 10). Триггеры процесса сделки в режиме загрузки отключены, историю и отзывы тестовых сделок пишем явно.
- **Даты.** Открытые сделки и публикации привязаны к моменту загрузки, иначе плановое задание сразу переведёт их в EXPIRED. Подписки продлены, иначе после 31.10 у поставщиков пропадёт доступ к сервису (условие 2.6).
- **Кейс A/B/C/D по новым правилам.** B 30 м, D 50 м, C 70 м внутри зоны 100 м; E 130 м не проходит п. 2.1. Агент 4 (D): блокировка в прошлом, сервис назначен компанией, рейтинг 3,95, клиент 1 с рейтингом 4,0 проходит его минимум 4,0. Порядок B, D, C сохраняется.
- **Такси.** Маршрут и цена по дорогам — на сервере (Э2). В БД сделка 7 и отклик водителя 6 хранятся с длиной маршрута 6,4 км и ценой по тарифу max(700, 150 × 6,4) = 960 тг.
- **Баллы.** У агентов 1, 2, 4, 5 не должно остаться сделок без баллов, иначе `provider_can_offer` вернёт `REVIEW_REQUIRED` и сценарии не пройдут.
- **Совместимость.** API v0.6 обращается к `deal_offer.is_selected` и `qr_token` — после загрузки старый сервер сломается на согласовании. Это ожидаемо: API переписывается на следующем этапе Э2, до тестов на эмуляторах.
- **Тестовые пользователи.** Вход по логину и паролю заменяет выбор агента из списка (`/dev/agents` остаётся только при `MP_DEV_LOGIN=1`). Пароль в репозитории не хранится: в `mp_service.sql` — хеш bcrypt, проверка — `crypt()` из pgcrypto, расширение ставится скриптом (`CREATE EXTENSION IF NOT EXISTS pgcrypto`). Таблиц становится 30 — поправить `02_db_architecture.md` и ТЗ (раздел API 4.1) на Э8.
- **Переходы.** В справочнике 18 переходов (в шаге 7 ранее ошибочно указано 19).
- **Отклонение от документации.** Тексты уведомлений хранятся в глоссарии типа уведомления (`NOTIFY_TYPE`, коды 30091+), а не в отдельном диапазоне 60000+. Документ `02_db_architecture.md` поправить на Э8.

## Итог (25.10.2026)

- `mp_service.sql` v0.7 загружается в PostgreSQL 17.6 без ошибок: 30 таблиц, 14 представлений, 35 функций, 17 триггеров.
- `db/tests/01_rules.sql`: 29 тестов (12 проверок целостности и 17 сценариев), все проходят; данные после прогона не меняются.
- Добавлено по ходу проверки: цена отклика должна быть в пределах настроек поставщика (`PRICE_OUT_OF_RANGE`), иначе обещание раздела 6 алгоритма не выполнялось.
- Тестовые пользователи `user_testing_1…5` входят по общему паролю (агенты 7–11), в репозитории только хеш.
- Не покрыто тестами БД: маршрут такси по дорогам и код закрытия — это задачи сервера (Э2).
