## 2. Цель и объём

**Цель:** прототип маркетплейса услуг, на котором на двух эмуляторах проходит полный цикл сделки «клиент ↔ поставщик» по алгоритму v0.7, с выбором шаблона интерфейса, цветовой схемы и языка.

**Входит:**
- БД v0.7 (миграция, триггеры, функции, тестовые данные).
- API v0.7 (раздел 4).
- Android-приложение на Jetpack Compose: вход тестовым агентом, настройки (шаблон / схема / язык), поиск услуг, запрос, публикация окна поставщиком, входящие запросы и отклик, отклики на карте и списком, согласование, маршрут, сближение, закрытие кодом, баллы, отмена.
- Три шаблона интерфейса A, B, C × схемы LIGHT, DARK — одна логика, разные раскладки.
- Режим тестирования администратора.
- Такси с маршрутом по дорогам OSM (GraphHopper).

**Не входит:** регистрация нового агента, оплата, финансовый кабинет (только просмотр рейтинга), офлайн-пакет MBTiles, push через FCM, реальная авторизация, MCP.

## 4. API v0.7

Базовый адрес `http://127.0.0.1:8080/api`. JSON в UTF-8; время — ISO 8601 локальное (`2026-10-24T18:00:00`); деньги — числа в валюте `currency`. Тексты — на языке из заголовка `Accept-Language` (`RUS`/`ENG`), по умолчанию язык агента.

### 4.1 Авторизация (только для разработки)

| Метод | Путь | Тело / ответ |
| --- | --- | --- |
| GET | `/dev/agents` | Список тестовых агентов: id, псевдоним, роли, `is_testing` (включено только при `MP_DEV_LOGIN=1`) |
| POST | `/session` | `{"agent_id": 1}` → `{"token": "...", "agent": {...}}` |

Дальше заголовок `Authorization: Bearer <token>`. Токены — в памяти сервера.

## 5. Android-приложение

### 5.1 Структура модулей кода

```
app/src/main/java/ru/mpavel/osmmap/
  MainActivity.kt          одна Activity, setContent { App() }
  core/net/                HTTP-клиент, токен, ошибки API
  core/config/             загрузка ui_config, кэш по контрольной сумме
  core/theme/              MpTheme из палитры JSON, шрифты, формы
  core/i18n/               тексты глоссария: t("ui.find_providers")
  core/icons/              SVG из БД, подмена currentColor
  core/location/           источник положения: GPS или курсор (тестовый режим)
  data/                    модели и репозитории (services, deals, offers, slots, notifications)
  feature/login/           выбор тестового агента
  feature/settings/        шаблон / схема / язык
  feature/home/            главная: поиск, категории, активные сделки, карта публикаций
  feature/request/         создание запроса
  feature/offers/          отклики и согласование
  feature/deal/            сделка: маршрут, сближение, закрытие, отмена
  feature/provider/        публикации, входящие запросы, отклик, настройки сервиса
  feature/review/          баллы
  ui/template/             реализации экранов по шаблонам: a/, b/, c/
  ui/map/                  карта osmdroid, зона, маркеры, курсоры, перетаскивание
```

Единая модель: каждый экран — `ViewModel` с `UiState` и действиями; шаблон выбирает только composable-реализацию: `when (template.screens.offers) { "map_sheet" -> OffersA(state, actions); "cards_toggle" -> OffersB(...); "map_table" -> OffersC(...) }`. Логика, тексты и данные не дублируются.

### 5.2 Конфигурация интерфейса

1. При запуске: `GET /config?checksum=<сохранённая>`. `304` — используем кэш; иначе сохраняем новую конфигурацию.
2. Настройки: выпадающий список «Шаблон / схема» из `/ui/options` (`Шаблон A / Светлая`, `Шаблон A / Тёмная`, `Шаблон B / Светлая` …); фильтр «Светлая / Тёмная» сужает список. Язык — отдельный список.
3. Выбор применяется сразу (`PUT /config`), без перезапуска.

| Входящие запросы | поставщик | Список подходящих запросов, рекомендованная цена, «Откликнуться» / «Пропустить» | шторка | карточки | как эскиз C4 |
| Настройки сервиса | поставщик | Зона, время, цены, тариф (класс, порог, цена за км), автоотклик | общий | общий | общий |
| Профиль | оба | Псевдоним, роли, рейтинг по сервисам, режим тестирования (только просмотр) | общий | общий | общий |

Общие требования: зоны нажатия ≥ 48 dp; контраст текста ≥ 4.5:1; нижние элементы не заходят под системные панели; ошибки сети — понятный текст и повтор.

### 5.4 Карта

- Подложка — тайлы OSM из справочника `MAP_BASE_LAYER` (`OSM` для тестов), уникальный User-Agent, подпись «© участники OpenStreetMap» поверх карты.
- Слои: точка и круг зоны клиента; маршрут А → Б и коридор (такси); отклики / публикации с подписью «псевдоним · ★ рейтинг · цена»; курсоры сторон.
- Курсоры — из `/config` (`cursors`): «капля» или «капля с шестерёнкой» по `is_testing` агента, цвет по роли. Шестерёнку видят все.
- Режим тестирования: свой курсор перетаскивается; при отпускании — `PUT /me/position` с `source = manual`. В обычном режиме — GPS (разрешение на геолокацию), отправка раз в 10 с на экранах сделки.

## 6. Код закрытия

```
interval  = floor(unix_time / ttl_s)                 ttl_s = close_qr_ttl_s | close_key_ttl_s
code      = HMAC_SHA256(deal.close_secret, deal_id || ":" || interval) → 31 бит → mod 10^len, с ведущими нулями
qr_payload = "mpclose:" || deal_id || ":" || code
принимается: code(interval) или code(interval - 1)
```

- `close_secret` — 32 случайных байта, создаётся при AGREED, клиенту не отдаётся никогда.
- Поставщик получает код через `GET /close/code` и обновляет его по `expires_at`.
- Клиент сканирует `qr_payload` или вводит цифры.
- Проверки сервера: клиент сделки; статус CONTACT (гео-услуги) или AGREED (`place_mode = online`); код действующий. После CLOSED — уведомление `REVIEW_REQUIRED` обеим сторонам.
- Тестовый режим: `test-scan` подставляет действующий код; `test-provide` отправляет клиенту уведомление `CLOSE_CODE`, приложение клиента сразу вызывает `POST /close` с кодом из уведомления (только если клиент тоже в тестовом режиме; иначе клиент вводит код вручную).

## 7. Безопасность прототипа

- Пароль БД и секреты — только в переменных окружения (`MP_DB_PASSWORD`, `MP_GEO_SECRET`), не в коде и не в Git.
- Вход по `agent_id` — только при `MP_DEV_LOGIN=1`.
- Открытый HTTP разрешён только до локального API (`network_security_config.xml`).
- Персональные поля другой стороны отдаются только по `show_stage` и статусу сделки.
- Точное место и имя поставщика до согласования не отдаются ни в одном методе.
