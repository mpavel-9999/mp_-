## Структура

- `graphify-out/` — Граф для Cloud по ведению проетов
- `project_osm_map/` — Android-приложение с картой OpenStreetMap (osmdroid, без ключа API)
  - сборка: Android Studio → Build → Build APK(s), или `gradlew assembleDebug`
  - AGP 9.4.0, Gradle 9.8.2, compileSdk/targetSdk 37, minSdk 24, Kotlin встроенный в AGP 9, версия поднята до 2.4.21
    (`buildscript` в корневом `build.gradle.kts`; встроенный 2.2.10 не читает текущие библиотеки)
  - `app/` — Compose, Material 3: `core/` (сеть, конфигурация с кэшем по сумме, тема из палитры, тексты, SVG),
    `data/` (модели и репозитории API v0.7), `feature/` (вход, главная, настройки, профиль), `ui/` (карта, шаблоны A/B/C)
  - `server/` — локальный API на Java (HttpServer + JDBC) над схемой `mp_service`; запуск `gradlew :server:run`, пароль БД в `MP_DB_PASSWORD`
  - `db/mp_service.sql` — схема маркетплейса и тестовые данные (PostgreSQL 15+, удаляет схему целиком)
  - `docs/TZ_marketplace.md` — ТЗ маркетплейса (основной документ — в Claude Docs)
  - инструкция запуска — `project_osm_map/README.md`

  4. Временные файлы (пробные сборки, кэши) удалять после проверки; диск D: маленький (8 ГБ) — туда ничего не писать.
- Работа с БД:
  1. При создании объектов (таблиц, представлений, материализованных представлений и т.п.) всегда добавлять
     описание объекта и всех его полей (`COMMENT ON TABLE / VIEW / MATERIALIZED VIEW` и `COMMENT ON COLUMN` —
     в том числе для каждого поля представления). Проверка после загрузки скрипта: запрос по `pg_attribute`
     для `relkind IN ('r','v','m')` не должен находить ни одного объекта или поля без описания.
  2. При создании процедур и функций всегда добавлять описание (`COMMENT ON FUNCTION / PROCEDURE`), а внутри тела —
     комментарий: что она выполняет и кратко, ёмко — методику работы.
